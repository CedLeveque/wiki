Dans le monde industriel, il n'existe pas une unique "table" universelle, mais plutôt un ensemble de standards sémantiques et de modèles d'information qui définissent comment nommer et formater les données. Voici quelques références 

== 1. Les dictionnaires de propriétés (La Sémantique)
Pour la recherche d'une référence précise pour le nommage et la définition technique, deux standards dominent le marché :

* eCl@ss (Le plus utilisé en Europe)
C'est la référence pour la classification des produits et de leurs caractéristiques. Chaque propriété possède un ID unique (IRDI).
Pour une température : eCl@ss définit des propriétés comme "Operating temperature" ou "Process temperature".
Format : Souvent un nombre flottant (REAL) avec une unité liée (ex: degré Celsius).

* IEC 61360 / Common Data Dictionary (CDD)
C'est une base de données de l'IEC qui fournit des définitions normalisées pour les composants électriques et industriels. Elle définit le nom, le symbole et le type de données.

== 2. Les modèles d'information (Le Nommage)
Pour structurer le nom de la variable (ex: Spindle_Temp), on s'appuie sur des modèles qui organisent la hiérarchie.

* OPC UA (Companion Specifications)
C'est aujourd'hui le standard incontournable pour l'interopérabilité. Pour une broche (spindle), il faut regarder la spécification "OPC UA for Machine Tools" (anciennement Umati).
Noms normalisés : Les variables y sont nommées en anglais, souvent en PascalCase.
Exemple : Spindle/Temperature/ActualValue.
Format : Double ou Float (pour la précision décimale).

* ISA-95 (Intégration ERP/MES)
Ce standard ne donne pas le nom exact de la variable, mais impose une hiérarchie de nommage basée sur le contexte :
Entreprise.Site.Zone.Ligne.Machine.SousEnsemble.Variable

== 3. Exemple concret : La Température Broche
Si l'on doit mettre en place une normalisation interne, voici ce qui est généralement pratiqué en suivant les standards ISO 22400 ou VDI/VDE :

.tableau
[cols="30,70", options="header"]
|===
^| Aspect ^| Recommandation Standardisée 
| Nom technique (ID) | Spindle_Temp_Act ou Spindle_ActualTemperature 
| Type de donnée | FLOAT32 (ou REAL en ST) 
| Unité (UCUM) | Cel (pour °C) ou K (pour Kelvin)

|===

== 4. Vers l'Asset Administration Shell (AAS)
Le futur de la normalisation industrielle (Industrie 4.0) est l'AAS (ou Jumeau Numérique). L'AAS utilise des "Submodels" normalisés. Exemple pour une température :

* On utilise un dictionnaire (comme eCl@ss) pour dire : "Cette variable est une température".
* On utilise une structure OPC UA pour la transmettre.
* On utilise le format JSON ou XML pour la stocker.

Comment choisir ?

* Si l'on doit faire de l'intégration machine : Il faut suivre les Companion Specs OPC UA du secteur impacté (Machine Tools, Robotics, Pumps, etc.).
* Si l'on doit construire un Data Lake : Il faut utiliser le dictionnaire eCl@ss pour mapper les données provenant de sources différentes vers un nom unique.


== 5. Ou trouver les informations ?

Il existe plusieurs plateformes de référence pour consulter ces "tables" de données et ces modèles, selon que l'on cherche la documentation théorique ou le modèle technique (XML/NodeSet).

Voici les trois ressources principales pour les spécifications OPC UA et les propriétés industrielles :

=== 5.1. Le catalogue VDMA (Pour les machines et la mécanique)
Le VDMA (syndicat industriel allemand) est l'organisme qui pilote la majorité des "Companion Specs" pour les machines-outils, la robotique et le plastique.

Contenu : On y trouve la série VDMA 40001 (OPC UA for Machinery) et VDMA 40501 (Machine Tools).

Utilité : C'est ici que sont définis les noms exacts des variables (ex: SpindleTemperature) et leur emplacement dans l'arborescence.

Site : vdma.org/opc-ua (Recherchez "Companion Specifications").

=== 5.2. L'OPC UA Cloud Library (L'explorateur de modèles)
C'est une bibliothèque en ligne qui regroupe les modèles d'information (NodeSets) de presque toutes les industries.

Contenu : Des fichiers XML normalisés utilisables par les développeurs.

Le petit plus : Il est possible de rechercher par mot-clé (ex: "Spindle") pour voir comment les types d'objets sont structurés dans les différentes spécifications (Umati, PackML, etc.).

Site : uacloudlibrary.opcfoundation.org

=== 5.3. ECLASS Search (Le dictionnaire des propriétés)
Contenu : Chaque propriété a un numéro unique (IRDI). Par exemple, si l'on cherche "Temperature", on obtient sa définition, son format (ex: REAL), et ses unités autorisées.

Format de la variable : ECLASS spécifie si la donnée doit être un nombre décimal, une chaîne de caractères, etc.

Site : eclass-search.org
